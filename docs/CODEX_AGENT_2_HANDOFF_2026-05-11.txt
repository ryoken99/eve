Direcao tecnica recomendada agora
---------------------------------
Prioridade 1: Mission Ledger / Delivery Review hard gate
- Implementar objeto de missao para qualquer pedido com 2+ acoes ou ferramenta sensivel.
- Estados por passo: pending, running, verified, failed, skipped_with_reason.
- Resposta final so pode sair se todos os passos estao verified ou failed com explicacao.
- Se failed e houver reparacao segura, Eve deve tentar corrigir automaticamente antes de responder.
- Logar em logs/actions/dd-mm-aa.jsonl e memory/errors/dd-mm-aa.md.

Prioridade 2: Tool verification contract
- Cada tool deve devolver:
  tool, ok, verified, evidence, artifacts, cleanup_done, next_recovery.
- O LLM nao deve inventar sucesso. O runtime deve bloquear "feito" se verified=False.

Prioridade 3: Browser cleanup and single-tab research
- Garantir todas as pesquisas visiveis usam uma aba.
- Fechar aba ao final.
- Se Chrome perfil Eve nao estiver ativo, abrir com perfil Eve.
- Se abriu mais de uma aba, fechar extras e registar.

Prioridade 4: X posting robusto
- Preflight: idioma ingles por default para X, limite de caracteres, limpar caracteres estranhos.
- Execution: abrir X pelo perfil Eve.
- Verification: confirmar post no perfil/timeline ou pelo estado UI.
- Recovery: se texto longo, encurtar e repetir.

Prioridade 5: Continuity boot
- Ao iniciar UI/daemon, carregar:
  memory/long_term/sandro_profile.md
  memory/long_term/sandro_interests.md se existir
  state/eve_status.json
  state/active_goals.yaml se existir
  ultimos N resumos diarios
  tarefas cron pendentes.
- Mostrar no topo algo como "continuidade carregada: data, ultima sessao, tarefas pendentes".

Prioridade 6: Autonomy maturity
- A cada ciclo daemon barato:
  - verificar tarefas vencidas
  - verificar erros recentes
  - verificar pendencias de mission ledger
  - decidir se precisa LLM via token gate
  - se sim, criar missao de reflexao/correcao.
- Nao gastar tokens so por estar acordada.
