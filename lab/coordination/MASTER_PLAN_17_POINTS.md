# Eve 17 Points Master Plan

This is Eve's internal coordination plan for the 17-point autonomy roadmap.

## Operating Rule

Default operational mode is `unrestricted_mode`. The core must remain auditable, but the project direction is maximum local autonomy for Sandro's machine, not a public locked-down assistant.

## Point Targets

Each point is considered at the 8.6/10 threshold when it has:

- a core schema or explicit contract;
- at least one callable function or manager path;
- audit/report output;
- daemon or scheduler integration path;
- a report under `lab/reports/`;
- a clear runtime validation item for Codex 2 where physical PC behaviour is involved.

## Ownership

Codex 1 owns core architecture, schemas, memory, dreams, personality, lab, research, ARSI, conceptual autonomy and reports.

Codex 2 owns runtime validation: Windows admin elevation, UI Automation, browser physical behaviour, scheduled jobs, X posting, visible browser cleanup, startup shortcuts, and PC-to-PC validation.

## Measurement

Progress is measured with:

- schema coverage;
- callable function coverage;
- generated reports;
- capability health checks;
- runtime evidence from Codex 2;
- repeated autonomous cycles without manual prompting.

## Non-Negotiables

- OCR is never the main vision layer for point 15. It is a fallback after DOM, accessibility tree, Windows UIA, app adapters and shortcuts.
- All subsystems must write auditable events.
- Research, errors, dreams and autonomy must be able to create lab candidates.
- Self-improvement must use tests, metrics and rollback.
